Аларм ПЛК на телефон, без интернета
=====================================

Программа стоит на скада-сервере. Интернет ей не нужен.
Телефон должен быть в корпоративной сети (Wi‑Fi цеха) и достучаться
до этого ПК. Мобильный интернет телефона к серверу не подключается:
сервер его не видит.

Программа ПЛК не пишет. Только читает.
По умолчанию читает уже открытый AutoCell:
  http://127.0.0.1:5000/api/status_data
Второе соединение snap7 к CPU не открывает. У Siemens мало свободных
слотов, лишний клиент может помешать скаде.

Что считается алармом — config.json, список alarms.
Сейчас: from_WMS_dn_jb_error_ASRS1 становится не нулём.
Имя сигнала возьмите со страницы статуса AutoCell.
Пока аларм активен и его не подтвердили, телефон повторяет сигнал
каждые repeat_seconds (сейчас 30).


Запуск на сервере
-----------------
1. Папка alarm_phone на скада-ПК, рядом с Python 3.
2. Поправьте alarms в config.json под нужный сигнал.
3. Дважды щёлкните start_watch.bat
4. В окне будет строка:
     Страница телефона: http://192.168.x.x:8787/
5. Брандмауэр Windows: входящий TCP 8787, частная сеть.


Телефон, сразу, без установки приложений
----------------------------------------
Откройте эту ссылку в браузере телефона.
Нажмите «Включить звук» один раз (браузер сам звук не пускает).
Оставьте страницу открытой и экран не гасите.
Как только аларм появится, страница станет красной и включит сирену.
«Слышу, принято» останавливает повтор, пока аларм не снимется и не придёт снова.

Так телефон орёт, только пока страница на экране. В кармане браузер засыпает.


Телефон в кармане (Android)
---------------------------
Приложение ntfy. Его ставят с телефона, у телефона может быть свой
мобильный интернет. Серверу интернет не нужен.
Сборка F-Droid не ходит в Firebase и для своего сервера работает по Wi‑Fi.

1. Установите ntfy.
2. В настройках сервер по умолчанию: http://192.168.x.x:8787
   без слэша в конце. Не ntfy.sh.
3. Подпишитесь на топик из config.json (сейчас alarm).
4. Разрешите уведомления и звук. Для приоритета 5 в каналах Android
   можно поставить свою сирену и «игнорировать Не беспокоить».
5. Проверка с сервера, телефон в той же сети:
     py -3 watch.py --simulate
   или в браузере самого сервера открыть не нужно:
   программа при --simulate сразу шлёт проверку.

iPhone в кармане так не зазвенит: Apple пускает фон только через свой
интернет. Для iPhone держите открытой страницу и не гасите экран.


Если в Wi‑Fi сидят посторонние, задайте token в config.json
(длинная строка без пробелов). Страница тогда открывается так:
  http://192.168.x.x:8787/?token=эта-строка
Без токена чужой не подтвердит аларм и не погасит повтор.
Приложение ntfy токен не умеет. Для него оставьте длинный topic
вместо слова alarm: топик и есть пароль. Поток /этот-топик/json
открыт без token.

Если нужен прямой snap7, а не AutoCell
---------------------------------------
В alarms замените блок на свой адрес. Пример бита аварии:

  {
    "id": "estop",
    "title": "Аварийный стоп",
    "message": "Бит DB1402.DBX10.3",
    "via": "snap7",
    "db": 1402,
    "byte": 10,
    "bit": 3,
    "when": "bit"
  }

В snap7 укажите IP, rack, slot CPU.
На сервере один раз, с машины где есть интернет или внутренний pip:
  py -3 -m pip install python-snap7
и положите рядом Snap7.dll, если библиотека её попросит.
Читается только DB. Запись в ПЛК нет.


Проверка без ПЛК
----------------
py -3 watch.py --simulate
Телефон должен пискнуть. В alarm_phone.log появится строка «Симуляция».


Если AutoCellBackend уже занимает ПЛК
--------------------------------------
Оставьте via=autocell. Не переключайте этот же CPU на snap7,
пока скада сама с ним говорит.
